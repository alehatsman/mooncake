# docs-working

Working documents — strategic direction + per-stream active work +
the curated agent pickup list.

> **New to the repo?** Start at [`PICKUP.md`](./PICKUP.md) — it's
> the short ranked list of "what to work on, right now" with claim
> slugs and pointers into the deeper sources below.

## Layout

```
PICKUP.md                            Curated "what to work on" list — start here

vision/
  goals.md                           What Mooncake is, what "done" looks like
  non_goals.md                       What Mooncake refuses to become
  good_lessons_from_other_tools.md   What 30 years of provisioning got right
  bad_lessons_from_other_tools.md    The pathologies that killed prior systems
  kernel.md                          Kernel-package boundary + invariants
  sharing_and_modules.md             Git-native module sharing direction
  brainstorm/                        Multi-persona brainstorm runs + reusable PROMPT/FORMAT

streams/
  core/    specs/ proposals/ testing/   Typed actions, planner, executor (3 active specs)
  fleet/   specs/ proposals/ testing/   Multi-machine: agentd, transport, multiplexer (2 active specs)
  dx/             proposals/ testing/   init / doctor / history (no active specs)
  agent/   specs/ proposals/ testing/   MCP, transactions, ABI, secrets (2 active specs)

arch-report/                         Dated structural snapshots (one per pass)
code-review/                         Cold-read findings — F048 open, queue in TODO.md
specs/done/                          Pre-stream-restructure shipped specs (kept for inbound links)
archive/                             Completed one-shot docs (refactor-plan agent prompts, manual-test findings)
positioning.md                       Strategic positioning vs Ansible/Chef/Daytona
ARCH_SNAPSHOT.md                     Regenerated by scripts/arch-snapshot.sh — package graph + LOC
```

## How to use this

- **What to work on?** [`PICKUP.md`](./PICKUP.md). One curated screen.
- **New spec?** File under `streams/<stream>/specs/`. The stream README
  lists what's active and what shipped.
- **New code-review finding?** File under `code-review/findings/F<NNN>-<slug>.md`
  with frontmatter; add a row to `code-review/TODO.md`.
- **Strategic question?** Check `vision/` before proposing a feature.
  Especially `non_goals.md`: many proposals look reasonable until you
  see the historical receipts of why they kill projects.

## Conventions

- **Status of shipped work lives in commit history**, not in a separate
  PROGRESS.md. The v1 PROGRESS.md became its own maintenance burden.
- **Stream affiliation matters more than spec number**. Spec numbers are
  monotonic for history; what you actually want is "which stream owns
  this?" The folder hierarchy answers it.
- **Vision docs are short and stable**. If you find yourself updating
  them every week, the right place is probably a stream README, not
  vision/.

## What's *not* here (from v1)

- Long-form analyses of closed GitHub issues — they were valuable when
  the bug was open; once shipped, the fix lives in `git log -S<flag>`.
- The PROGRESS.md rev-N changelog — replaced by per-stream READMEs +
  commit history.
- `clustermanagement/` brainstorms and `analysis/` audits — exploratory
  one-shot docs that served their purpose. If a finding has lasting
  weight, it gets distilled into vision/.
- `epics/` — over-organized for a project at this scale. Stream READMEs
  carry the strategic frame.
