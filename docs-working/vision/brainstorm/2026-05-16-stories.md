# Stories from the 2026-05-16 brainstorm

Operational backlog derived from
[`2026-05-16-three-personas.md`](./2026-05-16-three-personas.md).
Pick one story at a time, claim it in `~/.mooncake/claims.jsonl`,
work it in a fresh worktree, surface follow-ups as new stories.

No timeline, no calendar. Stories advertise their dependencies; an
agent picks the next ready story off the list. Some stories are
genuinely independent and parallelizable — others gate on
predecessors and say so explicitly.

## How to pick a story

1. Read this file end-to-end first.
2. Read the **Hard rails** and **Forbid list** below before opening
   any story.
3. Pick any story whose listed dependencies are all `done` in
   `~/.mooncake/claims.jsonl`.
4. Claim it: append a `claimed` line to claims.jsonl with the
   story slug as `task`.
5. Create a worktree at `/home/aleh/projects/mooncake-<slug>`,
   branch `worktree-<slug>`.
6. Read the inputs listed in the story before writing anything.
7. Hit the definition-of-done. Surface follow-ups as new story
   entries appended to this file.
8. Don't commit/push unless the user explicitly asks.

## Hard rails (apply to every story)

- **Kernel test.** Every proposal either *adds to the kernel* (a
  new typed property, a sharper Diff shape, a deeper Reverse) or
  *adds a rendering* (a frontend, a UX command, an MCP tool). If
  neither, re-shape the work or stop. Source:
  [`docs-working/vision/kernel.md`](../kernel.md).

- **Seven non-goals.** No DSL evolution, no plugin marketplace, no
  control-plane sprawl, no git-coupled audit, no image
  monoculture, no ACID claims, no pipeline DSL. Source:
  [`docs-working/vision/non_goals.md`](../non_goals.md).

- **Voice discipline.** Internal docs (spec preambles, kernel
  refs) get Architect voice — "Mooncake is a typed mutation
  kernel." External strings (homepage, README hero, MCP tool
  descriptions, Loom voiceover, cold-DM, HN title) get Startaper
  voice — "Mooncake is the rollback button for AI agents touching
  your system" or a per-surface derivation of it. Catalog lives
  in [story `S-positioning-doc`](#s-positioning-doc).

- **70/30 ratio.** Until the `BOTTLENECK.md` inversion trigger
  fires, the work mix is 70% GTM + 30% kernel maintenance.
  Stories below mark themselves `GTM`, `kernel`, or `discipline`.

## Forbid list (do not propose stories for these)

These are blocked, not deferred. Adding work on any of them
requires writing why the corresponding forbid-trigger has fired,
in the brainstorm doc, before the story is even drafted.

- **Enterprise hub / L4 control plane.** Forbidden until two
  written agent-dev case studies exist on disk.
- **Fifth typed property (Determinism, Provenance, or any other
  candidate).** Forbidden in 2026. Review gated on the
  `BOTTLENECK.md` inversion trigger; see
  [`docs-next/decision-2026-fifth-property.md`](../../../docs-next/decision-2026-fifth-property.md)
  once `S-decision-doc-fifth-property` ships.
- **Parallel polish budget for solo-dev / dotfiles UX.** Solo dev
  is the funnel, not a wedge. Polish only what falls out of
  agent-dev work for free.
- **A sixth frontend.** Until the R-series refactor pays down the
  existing frontend duplication (kernel.md §"The frontends"), no
  new frontends.
- **Generic fact-provider plugin SDK.** `facts.repo_index` ships
  as a single typed action with a closed provider set; expansion
  goes through the normal spec path one verb at a time, not a
  generic SDK.

## The stories

Each story is self-contained. An agent picking one cold should be

### S-lighthouse-shortlist

- **Goal.** Produce a private, two-tracked shortlist of 6
  concrete people (3 per track) to cold-DM with the rollback
  Loom and the MCP-description before/after.
- **Type.** GTM. Operational. **Blocks `S-cold-dm`.**
- **Inputs.** Brainstorm §S.1, §S2.4. Your own Twitter/Mastodon/
  YouTube/Substack timeline; do not delegate the human work of
  identifying handles to an LLM.
- **Definition of done.**
  - File `~/.mooncake/lighthouse-shortlist.md` (NOT in any
    worktree, NOT in the repo) exists.
  - 3 handles in Track 1 (agent-burns-prod): independent dev,
    10k–100k reach, has publicly said words like "and then it
    deleted my X" or equivalent.
  - 3 handles in Track 2 (agent-tool-quality): someone who
    builds, evaluates, or audits MCP-driven agents and posts
    about agent capability/legibility.
  - Each handle annotated with: public URL where you found them,
    the specific post that qualified them, an approach angle.
  - No vendor employees (Anthropic / OpenAI / Google).
- **Dependencies.** None. Start now.
- **Note.** If this story stalls — if 6 concrete handles cannot
  be produced — that *is* the project's actual bottleneck and
  the work plan changes shape. Surface that finding as a
  follow-up story rather than guessing names.

### S-rollback-loom

- **Goal.** Ship a 30-second screen recording of the rollback
  demo. The single artifact the next 90 days of GTM is built on.
- **Type.** GTM.
- **Inputs.** Brainstorm §S.2.
- **Definition of done.**
  - Recording, ≤30 seconds total, three beats:
    - 0–8s: Cursor / Claude Code emits a `transaction:` block.
      Viewer sees typed YAML, not shell.
    - 8–18s: `mooncake plan --diff` renders the structural
      Diff. Step 3 intentionally fails on apply.
    - 18–30s: auto-revert. Steps 1 and 2 reverse. Final
      `mooncake history --json | jq` shows the audit trail.
  - Source `transaction:` example committed under
    `examples/transactions/loom-v1-rollback-demo.yml` (or reuse
    `examples/transactions/rollback-demo.yml` if it already
    serves).
  - Recording itself stored at a stable URL (asciinema / asset
    repo) — not committed to mooncake repo.
  - Voiceover or caption uses external canonical Startaper
    voice (cite `S-positioning-doc`).
- **Dependencies.** None for the recording; `S-positioning-doc`
  helps with voiceover wording but is not blocking.

### S-dogfood-mooncake-yml

- **Goal.** Ship `examples/dogfood/mooncake.yml` — a config that
  replaces the parts of this project's Makefile that map cleanly
  to existing mooncake actions.
- **Type.** GTM (credibility) + kernel (dogfood proof).
- **Inputs.** Brainstorm §"Prompt 1", Innovator §C.1, current
  `Makefile`.
- **Definition of done.**
  - File `examples/dogfood/mooncake.yml` exists.
  - Implements at least: build (`make build`), test
    (`make test-race`), ci (`make ci`).
  - Uses *only* existing YAML keywords (`shell`, `file`,
    `on_change`, `requires`, `unless`, `transaction`). **No new
    YAML keywords for the dogfood's sake** — if a Make pattern

    document why.

  - README in `examples/dogfood/` calls out what it does, what
    it intentionally doesn't do, and that this is a *credibility
    flex*, not a replacement.
  - Release-blocker on the next minor (Synthesis line ~1018);
    surface in `ROADMAP.md` or equivalent.
- **Dependencies.** None.

### S-explain-spec

- **Goal.** Ship `docs-working/streams/core/specs/spec-XX-explain.md`
  — the spec for `mooncake explain <noun>` + MCP `explain` tool +
  the `op_id` schema decision.
- **Type.** Kernel.
- **Inputs.** Brainstorm "Prompt 2" reframe, Innovator §α + §C.2,
  Startaper §S2.2.
- **Definition of done.**
  - Spec file exists with normal preamble (problem, motivation,
    non-goals).
  - Noun set defined: at least `<action-name>` (e.g., `pkg.install`),
    `<run-id>`, `<resource>`, `<op-id>`. Each returns typed
    schema + applicable examples + Diff/Reverse shape + spec
    origin.
  - MCP tool `explain(noun)` defined with JSON Schema for input
    and output.
  - **`op_id` schema decided in the preamble.** Position: FK
    into a separate `ops` table, not a flat column on the run
    record. Justification: covers the three failure modes
    named in Innovator §α (plan-with-no-run, rollback-as-one-op-
    reversing-N-runs, replay-of-replay) without forcing a
    destructive migration later. Two extra lines of migration
    today; saves a migration during a future lighthouse case
    study.
  - One spec, not two. `op_id` does not get its own spec.
  - Source-of-truth note: pulls from `schema.json` + handler
    metadata + runlog. No RAG, no embeddings.
- **Dependencies.** None for the spec; implementation is a
  follow-up story.

### S-vscode-extension-prototype

- **Goal.** Prototype an IDE extension (VSCode or Zed) that
  renders the typed `Diff` from `mooncake plan` inline in the
  gutter of any open `mooncake.yml`.
- **Type.** GTM (teaches the kernel claim viscerally).
- **Inputs.** Innovator §A.10, §E. Existing `mooncake plan
  --json` output shape.

  the plan JSON shape is already there. Can run in parallel

## What to do when you finish a story

1. Append `done` to claims.jsonl with the commit SHA if any.
2. If the story surfaced follow-ups, add them as new `### S-…`
   entries at the bottom of "The stories" section above.
3. Don't write a retro; the commit message + claim note is
   enough.
4. Pick the next ready story off the dependency graph.

## What to do if you can't finish a story

1. Append `abandoned` to claims.jsonl with a one-line reason.
2. If the blocker is a missing decision, surface it as a
   question to the user; do not invent the decision.
3. If the blocker is a missing dependency, the dependency was
   wrong — fix the graph above.
